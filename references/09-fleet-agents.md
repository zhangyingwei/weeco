# Fleet Agents（fleetagents.dev）参考

> **源码未获取，基于官方文档**：`github.com/derekennyAI/agent-platform` 链接已 404，站点当前只提供营销页与 3 篇博客（2026-08-03 / 08-10 / 08-17），无可下载代码或架构文档。以下事实均来自 fleetagents.dev 官方页面，无法用源码交叉验证。

## 1. 一句话与定位

Fleet（现名 Fleet Personal，by ennyAI）是面向个人的常驻 AI 助理：跑在一台常开的 Mac 上，用户用 iMessage 或 Telegram 像发短信一样派活（提醒、邮件分诊与起草、研究、晨报、持续监视）。闭源、订阅制（beta 29 美元/月，另需自备 Claude 订阅），仅 macOS。站点称“原始开源 Fleet”另有 Fleet Business 产品线，但其 GitHub 仓库已不可访问，许可证与源码均无法确认。**对“工程 Agent 舰队”的参考价值低**：它不是多角色开发编排器，而是单 agent 的个人助理。

## 2. 架构与运行方式

- 执行体在用户自己的 Mac 上，不在厂商云；官方明确“没有 Fleet 云保存你的生活数据”。
- agent 拥有独立的 Apple Account 与 iMessage 地址，因此默认只看到用户主动发给它的消息；用户可选连接邮箱/短信。
- 连接 Claude 账户作为模型来源；引导式安装（浏览器向导，无需 Terminal、无需管理员密码）。
- 消息、邮件、记忆、保存的登录凭据都留在该 Mac；凭据“scrambled”（加密）后本地存储。
- 支持 Telegram 作为无 iPhone 的替代通道；家人/信任联系人可用独立线路联系该 agent。
- 常开模式下每小时向厂商发一次健康心跳，只含状态元数据，不含消息/文件；用于发现卡死的 agent 并远程修复，可一键关闭。
- 建议用一台“备用 Mac”常开，避免笔记本合盖休眠导致提醒/晨报不触发。

## 3. 角色与任务模型

- 只有一个“个人助理”角色，没有 planner/doer/reviewer 等分工，也没有公开的任务 schema、角色文件或输出契约。
- 任务以自然语言消息表达。公开能力面：一次性/周期性提醒、收件箱分诊与摘要、按用户语气起草回复、研究问答、每日晨报、持续监视（standing watches，“银行来邮件就告诉我”）、把通话转录整理成待办、替用户使用网站（保存的登录可填表/查门户）。
- “家庭线路”是一种受限委派：信任的人可以给 agent 发消息，但用户决定它能为他们做什么。这是公开材料里最接近“角色权限矩阵”的设计。
- 记忆：偏好、项目、过往决定跨会话保留，避免重复解释；具体存储格式未公开。

## 4. 状态、调度与恢复

- 调度能力是产品级的“提醒/周期任务/持续监视”，但没有公开的状态枚举、队列、重试、租约或作业 ID。
- 恢复主要靠“常开 + 每小时健康心跳 + 厂商侧修复卡死 agent”；没有公开的崩溃恢复、断点续跑或会话恢复协议。
- 对外可见的状态只有消息对话本身；没有 CLI/API 文档说明如何查询任务状态。
- 因此无法从公开材料判断其幂等、去重、错过提醒补发等关键语义。

## 5. 隔离与权限

- 身份隔离：agent 用独立 Apple Account/iMessage 地址，默认看不到用户自己的短信，这是“最小可见性”的朴素实现。
- 数据隔离：本地存储、本地加密凭据、无厂商云副本；模型调用不可避免会把提问发给模型提供方，官方对此有明确说明。
- 审批 gate：发送邮件、删除内容、给新联系人发短信等“出境或不可逆”动作，必须先向用户展示收件人/主题/正文并得到 yes；这是其最明确的权限规则。
- 家庭线路的作用域由用户配置，但没有公开的 allowlist 语法、审计日志或沙箱细节。
- 没有公开的容器/沙箱/网络出口控制；安全模型主要建立在“本地 + 审批”上。

## 6. 可借鉴清单（映射 7 组件）

口径：C1 角色与载体矩阵、C2 终态协议、C3 事件驱动协调、C4 审查者工具白名单与审查台账、C5 单写租约与幂等派发、C6 上下文预算与状态包交接、C7 权限预检；下列简称均按此对应。

- 角色载体矩阵：家庭线路的“同一 agent、不同委托人、不同能力”提示我们，角色矩阵可以不按 agent 复制，而按“委托人 × 能力集”授权；但它缺少可复用配置格式。
- 终态协议：无公开协议，参考价值低；只能借鉴“出境动作必须人工确认”这一终态前 gate。
- 事件驱动：standing watch（条件满足才说话）+ 每小时心跳，是“事件触发 + 健康事件”的轻量组合，可对应我们的监视器与心跳。
- 审查白名单/台账：无台账；审批前展示收件人/主题/正文，是可移植的“审查摘要”最小字段集。
- 租约/幂等：无公开机制，不可借鉴。
- 上下文交接：跨会话记忆（偏好/项目/决定）是个人助理的核心，可借鉴“记忆是交接载体”，但无 schema。
- 权限预检：独立 Apple Account + 默认不可见 + 出境动作审批，三者构成“身份隔离 → 数据最小化 → 动作确认”的预检链。

## 7. 不可照搬与风险

- **相关性低**：单用户个人助理，不是多 agent 工程舰队；没有角色编排、代码审查、任务 DAG、租约、审计。
- **不可验证**：无源码、无许可证、无架构文档；博客是营销内容，机制描述停留在产品层。
- **原开源仓库消失**：`derekennyAI/agent-platform` 404，站点 “original open-source Fleet” 指向死链；不能据此推断其实现。
- **产品假设不同**：29 美元/月 + 自备 Claude 订阅、Mac 常开、依赖 Apple 账号，均不适合作为团队基础设施。
- **安全边界薄**：依赖本地信任与人工审批，没有公开的沙箱、网络出口策略、密钥分域或多租户隔离。
- 若团队真正需要“Fleet Agents”式多 agent 平台，应优先参考 apra-fleet / herdctl，而不是本项目。
