# weeco

在 Herdr 中用真实成员协作完成目标，由当前会话负责组织、参与执行和检查结果。

v0.11.0 将入口收敛为一个公开技能 `/weeco <目标>` 和五个协作命令。当前 Herdr 会话是唯一负责人；成员在同一 tab 的独立 pane 中工作，主 pane 保留。人数包含负责人，简单任务由负责人加 1 名成员完成，复杂任务根据交付物、依赖和所需能力增加成员。负责人也可以执行具体工作。

## 安装与使用

从源码构建需要 Go 1.24+。运行团队需要可用的 `herdr`、已完成登录且可正常工作的 `claude`，以及 Herdr 中的负责人 pane。

```bash
make install
```

已有二进制可运行 `weeco install` 安装技能。默认二进制位于 `~/.local/bin/weeco`，唯一技能位于 `~/.claude/skills/weeco/`，成员提示随技能安装。

在 Herdr 中打开工作的目录，进入当前 Claude 会话并输入目标，例如：

```text
/weeco 把本地预览端口从5186改为5187，其他不动，验收能启动
```

无需项目初始化。安装不写项目 CLAUDE.md，不修改工作区信任或权限，不启用 bypass。技能只在显式调用 `/weeco` 时启用，普通对话按原有方式进行。

## 如何协作

负责人读取已有材料、明确目标和交付边界，按依赖与能力分工。只有会改变行动的缺口才问用户；既有授权内继续工作，不在每一轮重复问开工。用户只要计划、方案或草稿时，团队检查该产物后交付，不执行其中列出的操作。

成员必须是真实 Herdr Agent/pane，不能用 Agent/Task 工具或会话里的角色扮演代替，也不能递归招人。共享目录中的写入先明确归属，避免相互覆盖。成员提交成果和核验依据后等待，负责人检查实际产物与原始来源，发现问题后让相应成员返工。

独立检查需要独立读取原始要求和证据、尝试反例；换角色签字不能证明正确。检查深度随错误代价调整。idle、超时和“已完成”文字都不构成验收证据。

## 命令

| 命令 | 用途 |
|---|---|
| `start --name ALIAS --role TEXT --task FILE [--replace]` | 启动成员，首名成员自动建立 run |
| `status [ALIAS] [--wait --timeout SEC] [--json]` | 查询成员与当前工作，按需等待 |
| `send <ALIAS\|lead> --file FILE` | 给成员开启新 turn，或向负责人通信 |
| `report --turn N --file FILE [--blocked]` | 成员提交指定轮次的成果或阻塞 |
| `close [ALIAS] [--cancel --reason TEXT]` | 关闭指定成员或当前团队；取消需说明原因 |

以上命令均以 `weeco` 为前缀，支持 `--run ID` 显式定位。成员身份、任务、控制目录、当前 turn 和报告命令由 CLI 注入。报告归属成员 pane，必须携带收到的 turn，不能自动取最新轮次把旧结果冒充新结果。

`send lead` 只通信，送达不等于取得决定或授权。负责人在交付边界内检查并完成必要返工后再关闭成员；待用户决定或仍需返工时保留相关 pane。`close` 保留负责人主 pane，关闭动作本身不证明成果通过。

## 运行记录与边界

最小运行记录保存在 `~/.weeco/runs/<id>/run.json`，并保留任务、报告快照。CLI 管理成员与通信，成果仍由团队按实际任务交付；负责人核对当前版本、原始来源和实际观察，说明未验证项与剩余问题。

v0.11.0 采用新的扁平命令接口，不提供旧流程兼容层。安装器自动归档并移除旧 manifest 拥有的技能、模板和同名 slash 命令，保留用户自定义内容。升级不会回滚历史信任设置；归档位置与处理结果见安装输出。

## 开发与验证

```bash
go test ./...
go vet ./...
make build
```

自动回归覆盖成员生命周期、会话隔离、轮次检查、过期报告、阻塞、投递失败、等待和清理失败，并通过 `go test -race ./...`。手工驱动的真实双成员流程已覆盖启动、报告、原会话第二轮修改和关闭；真实 `/weeco` 方案与隔离代码修复任务已验证自主组队及成果检查，代码修复通过 11 项验收测试。

当前环境中，Claude Code 自动审批器曾拒绝成员的 `report`，将来自协作消息的 run 目标认定为缺少直接授权。该轮未正式提交，团队记录原因后取消关闭；这不属于完整自动流程通过。产物、运行状态和审批限制需要分别核对，这些小样本也不能证明任意领域任务都可靠。

完整操作示例见 [快速开始](docs/weeco-quickstart.md)。
